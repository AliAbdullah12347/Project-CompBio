# cohort_474 — the final analysis dataset

Generated by `../build_cohort.py` and `../impute_tobacco.py`. Do not edit by
hand; re-run the scripts.

**480 − 4 mix-ups − 2 unrecoverable = 474 samples.** No quality screen applied.

## Which file do I use?

| Task | File |
|:--|:--|
| Feeding CIBERSORT / CIBERSORTx | `mixture_TPM_hgnc_full_474.txt` |
| Any gene-level analysis (filter, TMM, voom, WGCNA) | `counts_474.tsv.gz` |
| Any model with covariates | `metadata_474_imputed.csv` |
| Normalising some other file to this cohort | `sample_list.txt` |

All four carry the same 474 samples **in the same order**.

**Tobacco is not in the expression files, and cannot be.** A counts matrix is
genes × samples; tobacco use is a property of a sample, not a gene. Adding it
as a row would make CIBERSORT deconvolve it as though it were a transcript. It
lives in `metadata_474_imputed.csv` and joins to the expression files by sample
title — which is why the column order is kept identical across all four.

## The files

**`mixture_TPM_hgnc_full_474.txt`** — 107 MB, 55,765 gene symbols × 474. TPM in
linear space, every column summing to 1e6, HGNC symbols, `GeneSymbol` header.
This is the CIBERSORTx upload. No gene was filtered out: 57,820 deposited rows
minus 47 ENSGR duplicates minus 2,008 rows sharing a symbol (summed) = 55,765.

**`mixture_TPM_hgnc_474.txt`** — 49.0 MB, 20,628 symbols × 474. Smaller
fallback for when the portal rejects 107 MB, restricted to protein-coding plus
IG/TR gene segments. Identical results for a run without batch correction,
since the regression only touches the 547 LM22 genes.

`CIBERSORTX.md` has the nine-step walkthrough, the reason for every setting,
and the full verification table.

Subset from the 480-sample mixture in `../../cibersortx/`. Subsetting after the
fact is valid **only** because that run had quantile normalisation and batch
correction switched off, which makes each sample independent of the others.
With batch correction on, the correction is fitted across the whole matrix, so
dropping a sample moves everyone else's fractions and the run must be redone on
exactly this set.

**`counts_474.tsv.gz`** — 16.1 MB, 57,820 genes × 474. Raw integer counts,
Ensembl IDs with version suffixes, all genes including `ENSGR` rows. Identical
in format to the deposited file, with the 6 unwanted samples removed and the
`.counts` suffix stripped from the column headers.

**`metadata_474_imputed.csv`** — 474 rows × 65 columns. Every covariate, with
tobacco imputed:

- `tobacco_imp_01` … `tobacco_imp_20` — **the twenty completed datasets.** Run
  your analysis twenty times, once per column, then pool with Rubin's rules.
  This is the only correct way to use them.
- `tobacco_observed` — the originals, blank for the 30 never reported. Kept as
  the audit trail.
- `tobacco_posterior_mean` — for plotting and sanity checks. **Never analyse it
  as though it were observed.** Collapsing twenty draws into one number throws
  away exactly the uncertainty the twenty exist to carry.
- `tobacco_was_imputed` — flag, for reporting and subsetting.
- `depth_ok`, `rin_ok` — quality flags, recorded but not applied.

**`sample_list.txt`** — 474 titles, one per line.

**`excluded_samples.csv`** — the 6 removed, with the reason for each.

## The 6 removed

**4 sample mix-ups** — `099252A`, `108773A`, `118140B`, `118141A`. Subject
identity errors reported by Krebs et al.; covariates complete, but the data
belongs to the wrong person.

**2 missing six of nine covariates** — `12R1998`, `13R1190`. Both missing age,
sex, tobacco and all three sequencing PCs. Imputing six variables from three is
invention, not recovery.

## Quality flags: recorded, not applied

`depth_ok` and `rin_ok` mark the 9 samples below 3,000,000 assigned reads and
the 4 with RIN below 5.0. They are **not** used to exclude anyone.

Krebs et al. state twice in their supplementary methods that no sample was
removed for low quality. They adjust instead: RIN and the three
sequencing-metric PCs enter every model as covariates, and voom's precision
weights exist, in their words, "to account for differences between samples in
sequencing depth". Excluding shallow samples on top of that corrects the same
problem twice with the blunter instrument, costs 13 samples of which 9 are
bipolar I, and adds a second diagnosis-associated filter (3.98% of BP1 against
1.71% of controls, Fisher p = 0.167) to a project whose contribution is
criticising the first one.

For the screened sensitivity analysis:

```python
screened = meta[meta.depth_ok & meta.rin_ok]     # 461 samples
```

**This departs from the submitted pre-proposal §3.5**, which committed to ≥3M
reads and RIN ≥5.0 as exclusions. Record it as a pre-specification amendment
before computing any result.
