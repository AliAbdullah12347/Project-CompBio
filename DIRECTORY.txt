 WHICH FILE DO I USE?
===============================================================================

 Four final files, all in data/cohort_474/, all carrying the same 474 samples
 in the same order. They are separate files because expression and covariates
 are different shapes, not because anything is unfinished.

   feeding CIBERSORT / CIBERSORTx  ->  mixture_TPM_hgnc_full_474.txt
                                       (step by step: CIBERSORTX.md)
   any gene-level analysis         ->  counts_474.tsv.gz
   any model with covariates       ->  metadata_474_imputed.csv
   normalising some other file     ->  sample_list.txt

 TOBACCO IS NOT IN THE EXPRESSION FILES, and cannot be. A counts matrix is
 genes x samples; tobacco use is a property of a sample, not a gene. Adding it
 as a row would make CIBERSORT deconvolve it as though it were a transcript.
 It lives in metadata_474_imputed.csv, joined to the expression files by the
 sample title, which is why all four files are kept in the same order.


===============================================================================
 !! ONE SAMPLE SET: 474
===============================================================================

 data/cohort_474/sample_list.txt is the canonical list. Normalise every other
 file in the project to it.

   480  deposited
    -4  sample mix-ups                 (fail deposited QC flag)
    -2  missing six of nine covariates (fail deposited QC flag)
   474  cohort_474

 NO QUALITY SCREEN IS APPLIED. Krebs et al. state twice that no sample was
 removed for low quality; they adjust instead, with RIN and the three
 sequencing-metric PCs as covariates and voom precision weights for depth. We
 follow them. depth_ok and rin_ok are recorded in the metadata, so the screened
 subset (461 samples) is one line away for a sensitivity analysis.

 The older 431-sample set in cibersortx/ is a strict subset: 444 deposited
 QC-pass minus 13 on quality. It needs rebuilding against sample_list.txt.

 data/make_mixture_full.py                                          [CODE]
   Builds the full-transcriptome CIBERSORTx mixture from counts_474.tsv.gz and
   the GENCODE v19 GTF. Computes TPM using UNION EXON length -- exon intervals
   are merged before summing, because adding transcript exon lengths naively
   inflates multi-transcript genes and deflates their TPM. Union is also the
   right denominator for HTSeq union mode, which assigns a read to a gene only
   if it overlaps that gene's exons and no other's.
   Run:  python data/make_mixture_full.py

 data/build_cohort.py                                               [CODE]
   Builds the 474-sample cohort from raw_as_deposited/. Removes 6 samples and
   nothing else -- no gene filter, no normalisation, no quality screen. Two
   exclusion rules: sample mix-ups and six-of-nine missing covariates. Depth
   and RIN are computed and FLAGGED but never applied. Derives every exclusion
   list by rule rather than by hard-coded ids, and fails rather than writing if
   the two raw files disagree on the sample set. Also subsets the 480-sample
   CIBERSORT mixture in cibersortx/ down to this cohort, when that file exists.
   Run:  python data/build_cohort.py

 data/impute_tobacco.py                                             [CODE]
   THE IMPUTATION METHOD WE USE. Fills the 30 missing tobacco values by
   drawing p* ~ Beta(1+smokers, 1+non-smokers) within each diagnosis group,
   then a Bernoulli draw per subject, repeated for m = 20 datasets, pooled by
   Rubin's rules. Reads no gene expression, so there is no circularity.
   Includes a self-contained Student-t implementation (scipy is not installed).
   Run:  python data/impute_tobacco.py
         python data/impute_tobacco.py --delta 0.912     (MNAR sensitivity)

 data/imputed_tobacco/                                            [OUTPUT]
   tobacco_imputations.csv          474 x 20 completed tobacco columns.
   pooled_estimates.csv             Rubin-pooled estimates, standard errors,
                                    95% CIs, degrees of freedom, fraction of
                                    missing information, and the
                                    assumption-free bounds alongside.
   imputed_subjects.csv             The 30 imputed subjects and the share of
                                    the 20 draws that called each a smoker.
   *_delta+0.912.csv                The same three files under the MNAR
                                    sensitivity analysis. Suffixed so a
                                    sensitivity run can never overwrite the
                                    primary result.

   WHERE delta = 0.912 CAME FROM. A now-deleted side experiment imputed tobacco
   from four smoking marker genes (GPR15, LRRN3, SEMA6B, CDKN1C) and found the
   30 missing subjects carry the smoker expression signature -- GPR15 z-score
   +0.46 against -0.42 for observed non-smokers and +0.94 for observed smokers,
   with plate, library size and RIN balanced between the groups. That implies
   the missing subjects smoke at roughly 37% rather than the observed 19%, a
   log-odds shift of +0.912. It is evidence the missingness is NOT at random --
   ordinary under-reporting of a stigmatised behaviour. Treat 0.912 as a
   calibration input estimated from expression, not a measurement, and report
   it as a range rather than a point.

 de_v2/   --  THE CURRENT DIFFERENTIAL EXPRESSION ANALYSIS
===============================================================================

 Added 2 October 2026. Supersedes de_analysis/ for results. No verdict bands;
 every multiple-testing correction applied to all four comparisons.

 WHY A SECOND FOLDER RATHER THAN EDITING THE FIRST
   de_analysis/config.yaml is a timestamped pre-registration -- hypotheses and
   decision rules committed before any analysis ran. Overwriting it would
   destroy the only evidence that the rules were fixed in advance. So v1 stays
   intact as the record, and v2 carries the analysis forward.

 WHAT CHANGED
   The 0.5% / 2% bands are gone. They turned "0.881% of genes" into
   "INCONCLUSIVE", which is strictly less information, and they were an
   uncorrected second decision layered on top of the gene-level testing.
   v2 reports quantities and their uncertainty, with thresholds as columns in
   a table rather than as verdicts.

 WHAT IT REUSES (as input, not as results)
   ../de_analysis/data/prep.rds            filtered counts, TMM, ILR balances
   ../de_analysis/results/bmind_profiles.rds   3.1 h of deconvolution
   Both are independent of any threshold and of the group labels, so
   re-running them would reproduce the same numbers. No v1 RESULT is read.

 READ THESE TWO FIRST
   README.md                         [DOC]  What is here, how to run it, which
                                     file answers which question.
   DECISIONS.md                      [DOC]  Every decision and its
                                     justification, 12 sections.

 SCRIPTS -- run in order; 00 gates everything after it
   scripts/mtc.R                [CODE] Correction library: Storey q-values,
                                Benjamini-Bogomolov, permutation FDR,
                                independent filtering. Hand-written because
                                qvalue/IHW/fdrtool are not installed and
                                CLAUDE.md forbids adding a dependency unasked.
   scripts/00_validate_mtc.R    [CODE] Proves mtc.R correct BEFORE it touches
                                real data: 14 exact identities plus a
                                known-truth simulation. Must print ALL CHECKS
                                PASSED or nothing below is trustworthy.
   scripts/01_refit_and_mtc.R   [CODE] Re-fits all four comparisons from
                                scratch, applies the whole correction panel.
   scripts/02_hierarchical.R    [CODE] Multiplicity ACROSS the five lineages
                                and ACROSS the four comparisons.
   scripts/03_permutation_fdr.R [CODE] Empirical FDR from 100 label
                                permutations -- the only correction here that
                                assumes nothing about gene-gene dependence.

 RESULTS
   summary_by_analysis.csv           THE HEADLINE TABLE. One row per analysis,
                                     counts under every correction.
   tests_<analysis>.csv.gz           Per-gene, every adjusted p-value.
   celltype_per_lineage.csv          Which lineage carries the signal.
   celltype_pooled.csv               Cell type vs whole blood, fairly compared.
   across_contrast_correction.csv    What running four comparisons costs.
   permutation_fdr.csv               Measured null vs the null BH assumes.
   correction_comparison.csv         All methods side by side.
   mtc_validation.csv                Measured error rate and power of each
                                     correction on data with known truth.

 THE ZEROS ARE NOT EVIDENCE OF ABSENCE
   Every lineage's detection floor exceeds the smallest effect anyone called
   meaningful; B cells would need a 72,000,000-fold change. No correction
   method can repair a power problem. See DECISIONS.md section 11.
